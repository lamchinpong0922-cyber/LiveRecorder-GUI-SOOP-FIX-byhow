【進行中】
4. SOOP 新版桌面播放器 API 與舊版備援 API 的回應結構驗證及診斷改善（已提交 GitHub，尚待本機整合驗收）。
5. SOOP 播放清單資料交接防護：新版桌面、舊版 watch、Global API 的播放清單若解析為空，改以已驗證的主 M3U8 網址作為備援項目（已提交 GitHub，尚待本機整合驗收）。
6. SOOP Mobile Watch API 狀態碼正規化：接受數字與數字字串的等價狀態碼，明確處理離線、成人限制、登入需求及未知/缺失狀態，避免未知回應被默認當成離線（已提交 GitHub，尚待本機整合驗收）。
7. SOOP 登入 Cookie 全流程、重試與並行保護：新版桌面 API 登入後即使串流解析失敗，也將新 Cookie 傳遞至舊版 API 備援；後續 API 失敗時仍保留新 Cookie；同一輪已完成桌面登入時不立即重複登入；舊版 CDN 沿用最新 Cookie；主程式以專用鎖序列化共用帳號的 SOOP 請求及 Cookie 更新，登入成功後即使請求例外也在釋放鎖前保存新 Cookie，設定檔讀寫另以程序內共用鎖避免多執行緒讀改寫互相覆蓋（已提交 GitHub，尚待本機整合驗收）。
8. SOOP 分階段 RESULT=0 與 AID 缺失處理：新版桌面 live 階段 RESULT=0 明確回傳離線，不進入舊版備援；desktop AID 階段仍保留舊版備援；舊版 AID 階段若 RESULT=0 且沒有 AID，視為本輪無可用串流，回傳未開播狀態並保留新 Cookie，不再產生 RuntimeError；其他異常 RESULT 仍保留例外診斷（已提交 GitHub，尚待本機整合驗收）。
9. FFmpeg 可用性檢查流程：移除 check_ffmpeg_existence() 在 finally 區塊中的 return，保留直接執行 ffmpeg -version 與安裝器 check_ffmpeg() 的既有判斷順序，避免 finally 的 return 壓制非預期例外；同時防止版本輸出行數不足時發生索引錯誤（已提交 GitHub，尚待本機更新及驗收）。
